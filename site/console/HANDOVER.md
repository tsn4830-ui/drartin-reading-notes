# 代謝共病態勢儀 — 交接文件

給接手這個專案的人（或 AI）。讀完這份就能繼續做，不需要原始對話。

---

## 1. 這是什麼

一個**單檔 HTML** 的臨床教學／衛教工具，把糖尿病、肥胖、高血壓、高血脂、慢性腎臟病
放在同一個介面裡，用三個尺度呈現：

| 尺度 | 內容 | 使用場景 |
|---|---|---|
| **病人** | 一位病人的器官風險地圖、六格遙測讀數、病程時間軸回放、11 種介入的情境推演 | 診間解釋、衛教 |
| **族群** | 台灣三高盛行率與知曉率缺口、末期腎病發生率國際比較、全球糖尿病人口 | 演講開場、公衛簡報 |
| **機轉** | 15 個節點、24 條因果邊的心腎代謝共病網絡，可逐步展開，可按治療看它切斷哪幾條邊 | 教學、講課 |

設計概念改編自 [bilawalsidhu/gods-eye-view](https://github.com/bilawalsidhu/gods-eye-view)
的圖層式態勢主控台：地球換成人體，即時資料圖層換成代謝指標圖層，
點擊追蹤換成點器官鎖定，運鏡回放換成病程時間軸，場景推演換成藥物介入推演。
**沒有沿用它的程式碼**（它是 Cesium + Vite；這裡是零依賴單檔）。

## 3. 硬性限制（請保留）

1. **單檔、零相依。** 只有三個 Google Fonts 連結是外部資源。
   不要引入 React / D3 / Tailwind / 建置工具。診間電腦與 iPad 要能直接開。
2. **病人資料絕不落地。** 使用者輸入的數值只存在分頁記憶體，
   不寫 `localStorage`、不上傳。`localStorage` 只用來記住「上次看的是哪個尺度」。
   這是刻意的隱私決定，不要為了「記住上次輸入」而改掉。
3. **單一深色主題。** 所有顏色顯式指定，不依賴瀏覽器主題。
4. **手機可用。** 約 400px 寬時三欄會收成一欄。

### ⚠️ 嚴重度色階 — 動之前請先讀這段

```
低風險 #93F2C8   中度增加 #E8C64E   高風險 #E08536   極高風險 #BE3B44
```

這四個值**不是隨便挑的**，也**不要為了好看重新調色**。

KDIGO 慣用的綠／黃／橘／紅，在紅綠色覺異常（約 8% 男性）底下，
綠和紅的 OKLab ΔE 只有 **2.6** — 等於整張熱區圖對這群人是糊的。
現在這組是重新分級過的版本，明度單調遞減，所以嚴重度同時被**明度**編碼：

| 檢查項目 | 原始 | 現在 |
|---|---|---|
| 色覺異常下最差配對 ΔE | 2.6 | **12.8** |
| 一般色覺最差配對 ΔE | 10.6 | **15.8** |
| 明度單調遞減 | ✗ | ✓ |

另外還有兩重備援編碼，也請保留：
- 器官節點的**外圈弧長**＝風險等級（0/3、1/3、2/3、3/3）
- 每一格 KDIGO 熱區、每一個標籤都**寫出風險帶名稱**，不靠顏色單獨傳達

如果要換配色，請用同樣的方法驗證：明度單調、色覺模擬下 ΔE ≥ 8、
一般色覺 ΔE ≥ 15、對比 ≥ 3:1。

## 5. 程式結構

全部在檔案末端的單一 `<script>` 裡，依編號分段：

| 段 | 內容 |
|---|---|
| 1 | 臨床常數：`BANDS`（四個風險帶）、`KDIGO` 熱區矩陣、`GCAT`/`ACAT`、`BMICAT`、`MEDS` |
| 2 | `CASES` — 三個內建案例，每個含 4–6 次就診 |
| 3 | 計算引擎：`egfrCKDEPI`、`kfre`、`metS`、`escRisk`、`derive` |
| 4 | `LAYERS`（6 個圖層）、`ORGANS`（8 個器官，各有 `score`/`rows`/`acts`） |
| 5 | `SIMS` — 11 種介入的族群平均效果 |
| 6 | 狀態 `S` 與病人尺度的所有 render 函式 |
| 7 | 族群尺度：`TW_PREV`、`TW_AWARE`、`ESKD`、`HERO`、`SOURCES`、`renderPop()` |
| 8 | 機轉尺度：`MN`（15 節點）、`ME`（24 邊）、`DRUGS`（8 種治療）、`STAGES`、`renderMech()` |
| 9 | 尺度切換：`MODES`、`setMode()` |

### 加一個器官
在 `ORGANS` 推一個物件：`{ id, nm, x, y, side:"L"|"R", layers:[], score(p,v,d), rows(p,v,d), acts(p,v,d) }`。
`x`/`y` 是人形 SVG 座標（viewBox `0 0 560 620`，人形已 `translate(130,0)`）。
`score` 回傳 0–3。

### 加一條機轉邊
在 `ME` 推 `["來源節點id", "目標節點id", "短標籤", "機轉說明"]`。
**注意：`DRUGS` 裡的 `cuts` 是 `ME` 的陣列索引**，所以在中間插入會錯位 —
要加請加在陣列末端，或同步更新所有 `cuts`。

### 節點視覺角色
`ROLE_OF` 把每個節點歸到 `up`（上游）/ `hub`（樞紐）/ `rf`（危險因子）/
`tod`（標的器官）/ `end`（終點），`ROLE` 定義各自的配色。
`SPINE` 是主幹邊的索引（畫粗線）。`COLS` 是頂部階段帶。

## 6. 臨床依據與刻意的取捨

**採用的標準**
- ADA Standards of Care 2026 — 診斷切點、HbA1c <7%、血壓 <130/80、CGM 指標、心腎保護用藥不受 HbA1c 限制
- KDIGO CKD — G1–G5 × A1–A3 分期與四帶風險熱區
- KFRE（Tangri 四變數）— 2 年與 5 年腎衰竭風險
- ESC — 心血管風險分類與對應 LDL-C 目標（<55／<70／<100／<116）
- 台灣 — 成人肥胖指引 BMI 分級與腰圍切點、國健署代謝症候群五項取三、高血壓指引居家 <130/80 與 722 原則
- CKD-EPI 2021（不含種族係數）由肌酸酐推算 eGFR

**四個刻意的決定，改之前請想清楚**

1. **沒有實作 SCORE2 迴歸式。**
   SCORE2 與 SCORE2-Diabetes 的係數是按歐洲四個風險區校正的，台灣不在任何一區內，
   直接套用會系統性偏差。改用 ESC 的**規則式風險分類**（確診 ASCVD、標的器官損傷、
   糖尿病病程、eGFR 分層、單一極端危險因子）— 指引明文、可稽核、不需外插。

2. **KFRE 只在 eGFR <60 時顯示。**
   該模型在 CKD G3–G5 族群開發與驗證，eGFR ≥60 外插沒有意義。
   頁面上會明講為什麼不顯示，不要為了「畫面比較滿」而拿掉這個閘門。

3. **健保給付條件只是提示性質。**
   SGLT2 抑制劑、GLP-1 受體促效劑、finerenone 的給付規定逐年修訂，
   目前只標「值得去查」而不宣稱符合。
   要寫成真正的判定邏輯，需要餵入權威條文版本（例如健保藥品給付規定 114.9.18）。

4. **沒有縣市別地圖、沒有成人 CKD 盛行率數字。**
   前者是政府資料開放平臺在原本的執行環境取不到；後者是找不到有把握引用的來源。
   **兩處都在頁面上明列為缺口，而不是用推估值填補。**
   如果要補，請用真實 CSV／有出處的數字，不要讓模型生成。

**族群尺度的數字出處（全部可回溯）**
- 過重及肥胖 50.3%、高血壓 26.76%、高血脂 31%、三高知曉率 68%／66%／23%
  → 國民營養健康狀況變遷調查 2017–2020（國民健康署）
- 糖尿病 12.8%（20 歲以上，FPG ≥126 或服藥）→ 國民營養健康調查 2019–2023
- 末期腎病發生率 2020 年：台灣 525、美國 396、新加坡 366、南韓 355、泰國 339、
  日本 307、印尼 303 pmp；中位數 146、最低厄瓜多 19 → USRDS Annual Data Report
- 台灣 2018 年發生率 523 pmp、盛行率 3,429 pmp，兩項世界第一
- 全球 20–79 歲糖尿病 5.89 億人（11.1%），2050 推估 8.53 億（13%）
  → IDF Diabetes Atlas 第 11 版（2025）

**情境推演的效果量**來自 DAPA-CKD／EMPA-KIDNEY／SUSTAIN／LEADER／FLOW／
SURPASS／SURMOUNT／FIDELIO-DKD／IMPROVE-IT／FOURIER／Look AHEAD／DiRECT 等試驗的
族群平均值，頁面上標明「非個人化預測，不可作為處方依據」。
